# 토스페이먼츠 — 심사 통과 후 라이브 전환 절차

**작성 2026-08-23.** 근거는 토스페이먼츠 공식 문서(「API 키」·「환경 설정하기」)와
실제로 띄워 확인한 결과다. 추정으로 적은 것은 없다.

**지금 상태** — 전자결제 **심사중**. 테스트 키로 결제위젯이 동작하는 것까지 확인했고,
**결제 승인(백엔드)은 아직 붙이지 않았다.** 이 문서는 승인 이후 할 일을 담는다.

---

## 0. 지금 어디까지 되어 있나

| | 상태 |
|---|---|
| 결제위젯 화면 | ✅ `/payment/toss` — 결제수단 선택·약관·결제창까지 |
| 사용 중인 키 | 밸류파인더 상점 **테스트** 클라이언트 키(`test_gck_…`), 코드에 상수로 |
| **결제 승인** | ❌ **없음.** `successUrl` 로 돌아오기만 하고 승인 API 를 부르지 않는다 |
| 크레딧 적립 | ❌ 없음 (승인이 없으므로) |
| 기존 PortOne 경로 | 그대로 살아 있음. 건드리지 않았다 |

**즉 지금은 「결제창이 뜨는 것까지」다.** 심사 자료용으로 만들었기 때문이다.

## 1. 키 — 세트를 맞춰야 한다

공식 문서 원문:

> *"클라이언트 키와 시크릿 키는 항상 '세트'로 묶여 있고, 한 세트로 써야 돼요.
> 세트가 아닌 키를 사용하거나 테스트 또는 라이브 키를 섞어 사용하면
> `INVALID_API_KEY` 오류가 발생해요."*

| 세트 | 클라이언트 | 시크릿 | 쓰는 SDK |
|---|---|---|---|
| **주문서형·결제창형** (우리) | `gck` | **`gsk`** | 결제위젯 SDK |
| API 개별 연동 | `ck` | `sk` | 결제창(구버전)·브랜드페이 |

**우리는 `gck` 를 쓰므로 시크릿도 반드시 `gsk` 여야 한다.** `sk` 를 쓰면 승인이 실패한다.

> **실제로 겪은 사고** — Vercel 에 `test_ck_D5GePWvyJnrK0W0k6q8gLzN97Emo`(API 개별 연동 키,
> 게다가 토스 문서의 공개 샘플)가 들어 있어 **라이브에서만** 위젯이 뜨지 않았다.
> 지금은 코드가 `gck` 형식일 때만 환경변수를 쓰도록 막아 두었다.

**API 버전** — 주문서형·결제창형 시크릿 키는 **`2022-11-16` 으로 고정**이고 바꿀 수 없다.

## 2. 라이브 전환 — 순서대로

### ① 라이브 키 확인

```
developers.tosspayments.com/my/api-keys
  → 상점: 밸류파인더
  → 라이브 탭
  → 클라이언트 키(live_gck_…) / 시크릿 키(live_gsk_…)
```

### ② 클라이언트 키 — Vercel 환경변수로

**코드에 라이브 키를 넣지 않는다.** 테스트 키는 상수로 두었지만 라이브는 다르다.

```
Vercel → frontend → Settings → Environment Variables
  NEXT_PUBLIC_TOSS_CLIENT_KEY = live_gck_…
```

**저장 후 반드시 재배포한다.** `NEXT_PUBLIC_*` 는 빌드 때 코드에 박혀서
환경변수만 바꾸면 반영되지 않는다. 빈 커밋(`--allow-empty`)은 Vercel 이 자동배포를
건너뛰므로, **파일이 바뀌는 커밋**을 올리거나 대시보드에서 Redeploy 한다.

### ③ 시크릿 키 — Railway 백엔드 환경변수로

```
Railway → backend → Variables
  TOSS_SECRET_KEY = live_gsk_…
```

공식 문서 원문:

> *"시크릿 키는 외부에 노출되면 안 돼요. **GitHub, 클라이언트 코드 등 외부에 보이는 곳에
> 추가하지 마세요.**"*

**코드·저장소·대화 어디에도 넣지 않는다.** 대표가 콘솔에 직접 입력한다.

## 3. 결제 승인 붙이기 — 이게 빠져 있다

**결제창에서 성공해도 그것만으로는 결제가 끝나지 않는다.** 승인 API 를 불러야 완료된다.

### 흐름

```
① 결제위젯 requestPayment()
② 성공 시 successUrl 로 이동
     {successUrl}?paymentType=…&orderId=…&paymentKey=…&amount=…
③ 프론트가 그 값을 백엔드로 전달
④ 백엔드가 시크릿 키로 승인 API 호출   ← 여기가 없다
⑤ 승인 성공 후에만 크레딧 적립
```

### 만들어야 할 것

| 무엇 | 어디 |
|---|---|
| 성공 콜백 처리 | `frontend/src/app/payment/toss` — 지금은 `?result=success` 로 돌아오기만 한다 |
| **승인 API 호출** | `backend/app/main.py` — `POST https://api.tosspayments.com/v1/payments/confirm` |
| 크레딧 적립 | 기존 `credit_transactions` 재사용 |
| 중복 방지 | `orderId` 유니크 제약. PortOne 의 `portone_id` 와 같은 방식 |

**반드시 지킬 것** — 쿼리로 돌아온 `amount` 가 **주문 때 정한 금액과 같은지 서버에서 확인**한다.
공식 문서가 명시한다: *"쿼리 파라미터의 `amount` 값이 메서드 파라미터로 설정한 `amount`와
같은지 반드시 확인하고 결제 승인 API를 호출해서 결제를 완료하세요."*
이 확인을 빠뜨리면 금액을 조작한 결제가 통과한다.

> 이 프로젝트에는 **결제창을 닫았는데 구독이 시작된 사고 이력**이 있다(CLAUDE.md).
> 그래서 프론트 응답을 믿지 말고 **서버에서 다시 조회해 확인**한다.

## 4. 테스트 환경에서 라이브와 다른 점

공식 문서 「환경 설정하기」에서 우리에게 해당하는 것만 추렸다.

| 항목 | 테스트 환경 |
|---|---|
| **결제 승인** | 실제 카드번호를 넣어도 **가상 승인**. 금액이 빠져나가지 않는다 |
| 카카오페이 | **계약 이후 상점용 테스트 키**로만 연동 가능 |
| 페이코 | **테스트 키로 연동 불가.** 라이브 키로만 테스트 |
| 가상계좌 | 계좌번호 앞에 `X` 가 붙는다. 개발자센터에서 입금처리 가능 |
| 정산 조회 | 테스트에서는 기록이 없는 것으로 조회된다 |
| API 요청 제한 | 분당 **100건** |
| 영수증 | URL 은 생성되나 실제 데이터는 없다 |

**테스트 결제내역** — `developers.tosspayments.com/my/payment-logs`
가상계좌 입금처리·결제 취소를 여기서 할 수 있다.

**에러 재현** — 헤더 `TossPayments-Test-Code: {에러코드}` 로 원하는 에러를 만들어 볼 수 있다.
`test_` 키에서만 동작하고 라이브에서는 무시된다.

## 5. 서버 준비

- **HTTPS + TLS 1.2 이상만** 지원한다
- 토스페이먼츠 **인바운드·아웃바운드 IP** 를 방화벽에서 허용해야 한다
- 웹훅을 쓸 경우 해당 포트를 열어야 한다

Railway 는 기본이 HTTPS 라 대개 문제되지 않지만, 웹훅을 붙일 때 확인한다.

---

## 6. 키 재발급 규칙

- 재발급 대상은 **시크릿 키·보안 키**뿐이다. **클라이언트 키는 공개 식별값이라 재발급 대상이 아니다**
- 재발급하면 기존 키는 **만료 예정**으로 바뀌고 **7일 안에 무중단 교체**할 수 있다
- 최대 2개가 공존하며 만료 전까지 **1회만** 재발급 가능
- **만료 전에 서버의 키를 교체하고 배포해야 한다.** 안 그러면 결제가 실패한다

```
□ Vercel  NEXT_PUBLIC_TOSS_CLIENT_KEY = live_gck_…   → 재배포
□ Railway TOSS_SECRET_KEY = live_gsk_…               → 대표가 직접 입력
□ 백엔드 승인 API 구현 (금액 검증 포함)
□ orderId 중복 방지 제약
□ 크레딧 적립 연결
□ 소액(1,900원)으로 실결제 1건 → 승인·적립·환불까지 확인
□ 결제 실패·취소 경로도 확인 (정상 경로만 보지 않는다)
□ 「테스트 결제 화면입니다」 배너가 사라졌는지 확인
□ PortOne 경로를 어떻게 할지 결정 (유지 / 정리)
```

| 요구 | 우리 |

지적 사유로 명시하므로 대비하는 편이 안전하다.

**다만 이 조항은 실물 상품 쇼핑몰을 전제로 쓰인 것으로 보인다.** 디지털 크레딧에도
그대로 적용되는지는 확인되지 않았다. 지적받으면 그때 카드마다 간단한 이미지를 넣으면 된다.

## 3. 신용카드 결제창 연동 — ✅ 완료

`/payment/toss` 에서 결제위젯으로 카드 결제창까지 열리는 것을 확인했다.

## 4. 계좌이체(퀵계좌이체) 입점 제한 — ✅ 해당 없음

불가 업종: 사행행위·게임머니·가상화폐·다단계·상조·대부업·자금세탁 등.
불가 구조: 출금대행, 정기 추심 납부서비스.

**우리는 AI 정보제공·상담 서비스이고 선불 크레딧 단건 판매**라 어디에도 걸리지 않는다.
구독(정기 추심)은 이미 접었으므로 「납부서비스」 조항과도 무관하다.

## 5. 금액 제한 — ✅ 통과

> *"카드사별 상품 금액 제한: **충전 서비스 10만원 미만**"*

우리 충전팩은 1,900 / 5,000 / 10,000원. **전부 10만원 미만**이다.

> *"**상품 금액과 결제 금액이 상이한 경우**"* — 심사 불가 사유

`/pricing` 과 결제창 모두 같은 금액(1,900·5,000·10,000원)을 보여주고 그대로 결제된다.
**지급 크레딧이 결제 금액보다 많은 것은 「덤」이지 금액 불일치가 아니다.**
다만 화면에서 **원 단위 금액이 항상 앞에 오도록** 유지한다 — 크레딧 수를 가격처럼
보이게 두면 오해를 살 수 있다.

## 6. 구비 서류 — 신청 경로에 따라 다르다

> *"**토스페이먼츠 홈페이지를 통해 신청하셨다면 우편물 발송 과정이 생략됩니다.**"*

우편 발송이 필요한 경우는 **가비아·고도몰·SIR소프트·메이크샵**을 통해 신청했을 때뿐이다.
카페24 바로오픈 PG 는 메일 링크로 진행한다.

**토스 홈페이지에서 직접 신청했다면 서류를 부칠 필요가 없다.** 어느 경로로 신청했는지
확인해 두면 불필요한 준비를 안 해도 된다.

(우편이 필요한 경우에만) 서울시 강남구 역삼로8길 15 홍우빌딩 4층 전자결제사업팀 · 06250
